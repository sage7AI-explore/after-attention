## 2. Referee items deferred from v0.11

Full analysis in `REFEREE_PASS_v0.11.md`. These were acknowledged in the paper
rather than fixed, which is honest but only once.

- **No τ sensitivity analysis anywhere.** §11.2 admits the stationary
  distribution depends on the revision protocol and τ, and no sweep exists.
  Run τ ∈ {0.05, 0.15, 0.30} on the headline configuration and show the
  qualitative findings are invariant. This is the cheapest credibility win left.
- **Model versions unpinned.** No snapshot identifiers, access dates, sampling
  parameters, or statement of whether a default reasoning budget was active.
  Note the tension with §8.7, where reasoning had to be explicitly disabled.
  Publish exact version strings and, if retrievable, provider request IDs.
- **Forty clusters.** The dof correction is minor, but the cluster-robust
  variance is downward-biased at G = 40 — which is what the sd(z) = 1.11
  calibration is detecting. Report CR2 / Bell–McCaffrey with Satterthwaite dof
  and a wild cluster bootstrap-t. Entirely feasible at this size.
- **The framing factor is designed in and never reported.** Five buying
  instructions, not one coefficient shown, and it bears directly on §8.5's
  premise that instruction context matters.
- **Assumption 2 versus μ_t = 3.** Re-run the headline at μ_t ∈ {10, 20}. If the
  knee sharpens, Proposition 1 is the mechanism. If it does not, something else
  is producing it and the paper must say so.
- **Δα resolution.** The claimed knee is one grid step wide at Δα = 0.1. Sweep
  [0.15, 0.4] at Δα = 0.02 and plot per-seller switch points.

## 3. Registration discipline

§8.6 now states in print: *"studies run after this paper are registered with a
registry before collection begins."* That is a public commitment. The
dose-response study and anything else new go to **OSF or AsPredicted**, not a
GitHub push. Push timestamps prove publication, not collection order — a
sceptical reader can point out a local pilot would be invisible.

Also worth doing retroactively and cheaply: anchor the SHA-256 of both existing
registrations with OpenTimestamps or an RFC 3161 authority, and mint a Zenodo
DOI for the repository snapshot. GitHub's public events feed is retained about
90 days, so the verification §8.6 describes expires.
